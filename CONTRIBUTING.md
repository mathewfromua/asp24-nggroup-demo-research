# Зміни й перевірка

Створіть тематичну гілку та draft PR із проблемою, base/head SHA, перевірками й залишками. Main і Pages змінюються лише після приймання. Не переписуйте історію чужих гілок.

Текст оглядів змінюйте тільки через `reports/content.json`; джерело, дату, метод і межу висновку записуйте окремо. Генеруйте обидва формати за `docs/DEVELOPMENT.md`. Для коду: `npm test`, `npm run build`, `npm run verify` та відповідні HTTP/браузерні сценарії. Не додавайте історичний PASS як результат нового коміту.

Збережіть stable ID, одиниці, імпорт, особистий стан і доступність. Шрифти, caches, секрети та приватні архіви не комітьте. Нові бібліотеки потребують конкретної задачі й зафіксованої версії; міграція renderer не є частиною редакційного випуску.
