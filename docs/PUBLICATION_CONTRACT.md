# Контракт публікації кандидата

`deployment.config.json` — єдине джерело origin і Pages-підкаталогу. `publication.json` — reportVersion, caseVersion, stable reportId/sectionId, fixture та семантична мета. Build обчислює entryURL/returnURL; рукопис використовує `{{CASE:id}}`. Наявні section ID схожі на старі номери сторінок, але відтепер заморожені й ніколи не перенумеровуються через верстку.

`index.html` після build — компактний статичний hub; каталог завантажується лише у `demo.html`. Малий legacy-entry зберігає старі root hash routes. `/reports/*_Review.pdf` та `.html` лишаються чинними. Чотири `/cases/<id>/index.html` і версійні `/cases/<id>/v1/index.html` працюють без server fallback. Static metadata доступні без виконання каталогу. Hub, reports, cases й каталог лишаються noindex,nofollow до окремого рішення; OG не означає індексацію чи реальну товарну пропозицію.

Кейс має окремий `sessionStorage` ключ `asp24-nggroup-case:<id>:v1`, fallback у пам’яті та власний reset. Адаптер ніколи не читає/записує особистий `perspective-demo-v1`; події іншої вкладки ігноруються у кейсі. Hash-навігація зберігає query контекст. Відновлення після перезавантаження гарантоване лише після успішного запису в sessionStorage. Недоступність сховища та помилки читання, запису й очищення мають окремий статус і видиме доступне повідомлення. Режим лише в пам’яті не позначається як збережений: користувачеві пояснено ризик reload і запропоновано JSON-експорт поточного навчального стану. Невдале очищення не запускає автоматичного reload. Копіювання URL не переносить персональних даних. Експорт прикладу містить його ідентифікатор, версію та schema 4; це не імпорт або приховане збереження в особисті проєкти.

Недійсні caseId/version дають пояснення й явне повернення; довільний JSON у URL не виконується. Усі приклади використовують production logic/data і чинне демо. Зміна frozen v1 fixture потребує нової версії, а не мовчазного переписування.

Ціль доступності — застосовні вимоги WCAG 2.2 AA, без заяви сертифікації. 44 CSS px — власний орієнтир touch-елементів. Широка таблиця має власний scroll; весь текст сторінки не повинен переповнювати viewport. Реальний zoom, VoiceOver і фізична клавіатура iPhone потребують окремої перевірки.
