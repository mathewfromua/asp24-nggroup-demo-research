# R42: повні огляди з логічними тегами — контрольований експеримент

`scripts/tagged-reports-experiment.py` розширює попередній односекційний pilot до **обох повних HTML-оглядів**. Це окремий шлях перевірки; він не змінює `reports/content.json`, генератори, manifests або прийняті PDF/HTML у `public/reports/`. R42 залишається відкритим. Опція `pdf_tags=True` не є заявою PDF/UA.

## Відтворення

Потрібні Python 3.12, системні Pango/Fontconfig, Poppler (`pdftoppm`) і ті самі дозволені шрифти Noto Sans, що використовуються основною генерацією. Версії Python-пакетів, включно з WeasyPrint 70.0, вже закріплені в `scripts/requirements-tagged-pilot.txt`. Шрифтові бінарники не комітяться.

```sh
python -m pip install -r scripts/requirements-tagged-pilot.txt
REPORT_FONT_DIR=/path/to/verified/report/fonts python scripts/tagged-reports-experiment.py
```

У cloud із недоступним user site packages використано каталог залежностей, а не нове середовище:

```sh
python -m pip install --target /tmp/asp24-tagged-packages -r scripts/requirements-tagged-pilot.txt
XDG_CACHE_HOME=/tmp/asp24-tagged-cache PYTHONPATH=/tmp/asp24-tagged-packages \
  REPORT_FONT_DIR=/workspace/cloud-onboarding/fonts \
  python scripts/tagged-reports-experiment.py
```

Результати зберігаються лише в ігнорованому `output/tagged-full/`: два PDF, точні print HTML/CSS, JSON-докази, усі сторінки обох комплектів, контактні аркуші та різниця рендеру обкладинок. JSON фіксує SHA, dirty status, UTC, версії renderer/Python/Poppler, hashes входів, шрифтів і виходів. Ці файли призначені для контрольного Actions artifact, не для публікації як основні огляди.

## Що фактично перевіряє інструмент

- Повний набір абзаців, заголовків, комірок, підписів із кожного розділу HTML присутній у витягнутому PDF-тексті. Нормалізується лише пробільна верстка і soft hyphen; числа, знаки, одиниці й назви не замінюються.
- Порядок кожного змістового блока перевіряється також через обхід `/K` дерева логічної структури та зіставлення `/MCID` зі справжнім текстом сторінок. Це предметніша перевірка за наявність `/StructTreeRoot`, але не заміна читанню допоміжною технологією.
- Перераховано H1/H2/H3/P/Table/TH/TD/Figure/Caption/Link; перевірено `/Lang`, ідентифікатори заголовків таблиць, `/Headers` кожної TD і розв’язність цих посилань, точні альтернативи ілюстрацій та закладки.
- Кожне посилання основного тексту звіряється з URI annotations PDF. Відносні адреси в print-копії стають абсолютними за чинним canonical; це не твердження про їхню публікацію.
- За наявності `verapdf` зберігається повний результат валідатора. Код виходу процесу сам по собі не тлумачиться як відповідність PDF/UA.
- Після завершення перевіряються hashes незмінених прийнятих PDF/HTML. Відсутній локальний asset припиняє генерацію; мережеві завантаження renderer заборонені.

## Межі print-адаптера

Читач PDF має отримати всі таблиці та текстові відповідники з HTML, зокрема точні дані графіків. Це може збільшити сторінковість проти ReportLab-версії. Інструмент не зменшує або не вилучає зміст заради 14/16 сторінок.

WeasyPrint 70 бере альтернативу SVG із `<title>`, а не з `aria-label`. Тому лише в print-копії точний наявний `aria-label` переноситься у `<title>`. Текст огляду й його джерела не редагуються.

У SVG presentation attributes print-адаптер також розгортає чинні `var(--accent)` / `currentColor` у точні кольори бренду. Без цього WeasyPrint показував графіки чорними; повторний рендер підтвердив апельсинові смуги ASP24. Усі відносні посилання й `.action` залишаються доступними в PDF: експериментальна print-таблиця стилів має авторський пріоритет над HTML-правилом приховування навігації під час звичайного друку.

Прийнята обкладинка раструється у 144 dpi й вставляється як Figure із повним текстом обкладинки у `/Alt`, усередині H1. Це зберігає композицію й палітру без небезпечного злиття нетегованої сторінки з тегованим деревом. Але втрачаються векторна різкість і звичайне виділення тексту обкладинки; H1 містить Figure, а не текстовий заголовок. Така обкладинка **не прийнята як заміна**. Pixel diff відкрито показує різницю растрування.

Структурні й текстові перевірки не доводять відсутності візуального обрізання, правильності всіх сценаріїв читання або відповідності PDF/UA. Для заміни основних PDF потрібні окреме повне візуальне приймання, придатний валідатор, перевірка читання і завершене рішення щодо обкладинок. Нативні VoiceOver та інші допоміжні технології не запускалися.

## Фактичний результат

09.10.2026 повна генерація виконана в Linux cloud після стабілізації критичного збереження RC2. Локальна робоча база — `3c289bf7c65400ea975427f8ed59721b97d77fe3` із явно незакоміченими уточненнями цього print-адаптера; точний fingerprint скрипту й dirty status записано у результат. CI повторює експеримент на SHA checkout після успішної браузерної матриці та зберігає окремий `tagged-reports-experiment-{SHA}` artifact. Локальний результат не підміняє CI на іншому SHA.

H1/H2/H3/P, Table/TH/TD, Figure/Caption і Link присутні; повний текстовий порядок, таблиці, числа, одиниці, підписи й вихідні альтернативи проходять контроль. Ці перевірки — `PASS`. Hashes усіх чотирьох прийнятих PDF/HTML після експерименту незмінні.

Візуально переглянуто контактні аркуші **всіх 33 нових сторінок**. Окремо збільшено ASP24 с. 6 (графік і повна таблиця), NG Group с. 9 (XPON) і с. 13 (гарантійний сервіс); у цих сторінках не виявлено обрізання змісту. Це не заявляється як детальна перевірка кожного рядка всіх сторінок.

Заміна основних PDF — **`FIX_REQUIRED`, експеримент не прийнято**:

- NG Group с. 5 містить лише коротку перенесену виноску «Зрозумілі назви»; с. 8 — коротке продовження пояснення часу роботи. Великі порожні ділянки та нова пагінація погіршують цілісність читання. Потрібне адресне узгодження print-переносів без вилучення змісту.
- Обкладинки зберігають початкову композицію і палітри, але растровані; обмеження тексту/різкості описане вище. Їх не можна оголосити структурно й візуально еквівалентною заміною прийнятих обкладинок.
- `veraPDF` у середовищі відсутній: валідатор PDF/UA — `NOT_RUN`. VoiceOver та інше фактичне читання допоміжними технологіями — `NOT_RUN`.

**R42 — OPEN.** Основні PDF залишаються без логічних тегів; HTML продовжує бути доступною альтернативою. Найближчий крок цього окремого напряму — виправити переноси та векторну семантичну обкладинку, після чого провести валідацію і читання; це не блокує завершений RC2 або окреме приймання Modern Experience.
