# RC3: незалежне читання інтегрованого кандидата

Версія `3.2.0-rc.3`, гілка `release/review-integrated-rc3`, база PR — `feat/modern-experience` на `a659d2f9e8d923a7bc64a3f91133cfed959e9181`. PR #7 і #8 — окремі контрольні точки. `main` та Pages не змінюються цим кандидатом.

## Вхід для рецензента

Завантажте RC3 HTTP-preview artifact з успішного workflow на SHA, наведеному в draft PR. Звірте SHA в `rc3-manifest.json` і hashes файлів. Запустіть доданий сервер командою з README пакета; `npm install` для перегляду готового `dist/` не потрібний. Два PDF і два HTML — фактичні виходи одного `reports/content.json`. Матриця рішень: [RC3_REVIEW_DECISIONS.md](RC3_REVIEW_DECISIONS.md); походження вхідного пакета: [rc3-preflight.json](rc3-preflight.json).

Перевірте в оглядах DC-виходи окремо від USB, розбіжність опублікованих діапазонів FHP12A та розділення історичної опори й отриманих PDF. Нові хеші не доводять тотожності старій копії або застосовності до конкретної поставки.

У `cases/six-candidates/v1/` відкрийте Modern Experience на 1440×900 та 390×844: без вертикального прокручування мають бути видимі назви моделей і повний перший технічний рядок. Замініть U05 на U07 та скасуйте заміну. Відкрийте картку або документ і поверніться посиланням та історією браузера: режим modern, шість кандидатів, пара, категорія й відмінності мають зберегтися. Повернення з прикладу веде до `asp24-09`. Особистий кошик і чернетки ізольовані.

## Межі кандидата

Статус публікації — `PREVIEW_NOT_DEPLOYED`. Абсолютні посилання PDF призначені для майбутнього Pages: доки власник не дозволив окреме розгортання, вони можуть вести до 404 або старого комплекту. Для зв'язаного перегляду використовуйте HTML у HTTP-preview. Локальний PASS не є прийманням реального HTTPS.

R34 залишається OPEN: початок і співвідношення сервісних строків не встановлені. R42 OPEN: фінальні PDF untagged, семантичний HTML — доступна альтернатива; PDF/UA не заявлено. Native Safari, фізичний iPhone, native zoom та VoiceOver — NOT_RUN. WebKit і вузький viewport не підміняють ці перевірки. Синтетичне демо не є магазином, реальною інтеграцією, комерційною пропозицією чи виміром конверсії.

## Контроль лише після окремого дозволу на публікацію

Цей список не запускає deployment і не надає дозволу на нього. На погодженому SHA після розгортання перевірити анонімним HTTPS-клієнтом:

| Адреси від Pages origin | Що підтвердити |
|---|---|
| `reports/ASP24_Review.pdf`, `reports/NGGroup_Review.pdf`, відповідні `.html` | HTTP 200, MIME, PDF signature, delivered SHA-256 і bytes за прийнятим manifest; предметні заголовки й посилання |
| `cases/six-candidates/v1/`, `cases/unknown-and-difference/v1/`, `cases/two-reels/v1/`, `cases/model-document/v1/` | HTTP 200, відповідний кейс, дія й повернення до `asp24-09`, `asp24-05`, `asp24-07`, `nggroup-09` |
| Ті самі чотири `cases/<id>/` без `v1` | Alias відкриває той самий frozen v1 без втрати контексту |
| `/`, `demo.html`, `publication.json` | Узгоджені version/SHA, hub перед демо, metadata/OG/noindex, усі активи за manifest |
| Старі hash links пошуку, карток, проєктів і документа | Реальний зміст, reload і Back/Forward; новий hub зберігає legacy-вхід |

Лише після цих перевірок можливий окремий статус `PUBLIC_RELEASE_VERIFIED`.

Наступна дія власника: незалежно переглянути exact-SHA RC3 artifact і залишити рішення про приймання у draft PR.
